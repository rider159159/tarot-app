# 功能名稱：互動抽牌模式（模式 B）

## User Story

作為想要更有占卜儀式感的使用者，我希望在首頁能切換到「互動抽牌」模式、親手從散開的牌堆點選指定數量的牌並逐張翻牌揭示，以便獲得「自己抽出這幾張牌」的參與感。

## 背景

- 現況首頁只有「直接占卜」：選牌陣 → 輸入問題 → 按鈕 → 直接顯示結果。
- 使用者主動設計此功能，目的是強化占卜儀式感，非新增占卜能力。
- 兩種模式並存，首頁以 tab 切換，預設「直接占卜」。
- 採路線一：後端零改動，後端照現有邏輯先抽好牌，前端只負責「互動選牌 + 逐張揭示」。

## Acceptance Criteria

- [ ] 首頁提供 tab 切換「直接占卜 / 互動抽牌」，預設停在「直接占卜」
- [ ] 互動模式流程：選牌陣 → 輸入問題 → 進入選牌畫面 → 點選牌 → 逐張翻牌 → 完整結果
- [ ] 選牌畫面顯示一堆牌背（統一偉特塔羅卡背圖），畫面至少 40 張，實際張數可隨機
- [ ] 每張牌背點擊有可選/已選的視覺狀態，已選數量即時顯示（如「已選 3 / 11」）
- [ ] 使用者需選滿「牌陣張數 N（含感受牌）」才算完成；未選滿不可結束
- [ ] **點一張、翻一張**：每點選一張牌，立即以 3D flip 動畫翻出該位置對應的後端結果（貼近現實抽牌）
- [ ] 翻出的牌依後端回傳順序對應到牌陣位置（第 1 次點選 = 牌陣第 1 位，依此類推）
- [ ] 全部翻完後，沿用既有 `ReadingDisplay` 呈現完整結果（含感受牌區塊）
- [ ] 桌面：扇形或網格佈局；手機：網格 + 垂直捲動（扇形無法容納 40+ 張）
- [ ] celtic-cross（11 張含感受牌）的手機選牌採網格 + 垂直捲動，可接受
- [ ] 未登入暫存流程（`pendingReading` / localStorage / clientToken）在互動模式下仍正常運作
- [ ] **原型先行**：先做 `CardPicker` + `FlippableCard` 原型，驗證牌堆佈局與翻牌動畫，再接真實資料流

## 技術影響

### 前端

- `routes/+page.svelte`
  - 新增模式切換 tab（直接占卜 / 互動抽牌），預設直接占卜
  - 互動模式下管理多階段狀態：選牌陣 → 選牌 → 揭示中 → 結果完成
- `routes/+page.server.ts`
  - 流程拆分為「先呼叫後端抽牌（結果暫不顯示）→ 前端互動 → 逐張揭示」
  - 互動模式下，draw action 回傳的牌結果先隱藏，交給前端控制揭示節奏
  - 登入走 `POST /api/readings`、未登入走 `POST /api/tarot/draw`，與現況一致
- 新元件 `CardPicker.svelte`
  - 渲染 ≥40 張牌背、處理點選、追蹤已選數量、回報點選順序
  - 牌背佈局：桌面扇形/網格、手機網格 + 垂直捲動
- 新元件 `FlippableCard.svelte`
  - 單張牌 3D flip（CSS `transform: rotateY` + `backface-visibility`）
  - 正面沿用 `CardResult` 的卡面內容或共用渲染
- 新資源：統一偉特塔羅卡背圖（放入 `lib/tarot/` 或 `static/`）
- 動畫：Svelte 5 內建 `transition:` / `animate:flip` / `crossfade` + 純 CSS 3D，無需新套件

### 後端

- 零改動。沿用 `POST /api/readings`（登入）與 `POST /api/tarot/draw`（未登入）。
- `TarotService` 的 Fisher-Yates 抽牌、正逆位邏輯不變。

### DB

- 無 migration。

### 第三方

- 無新外部服務。
- 無新 npm 套件（Svelte 內建動畫 + CSS 3D 足夠；拖曳手勢非本期範圍）。

## 優先級評估

- **使用者價值**：中 — 不新增占卜能力，純體驗/儀式感強化；對占卜重度使用者有實質感受提升。
- **開發成本**：M — 後端零改動，但選牌畫面 UX（40+ 張牌背的手機佈局、點一張翻一張的時序與狀態管理、揭示與既有 form action 流程整合）需要打磨。
- **學習收益**：Svelte 5 `transition` / `animate:flip` / `crossfade`、CSS 3D transform、SvelteKit form action 多階段流程拆分。
- **建議順位**：可排在 backlog 前段 — 成本可控、後端零風險、與既有功能無衝突。

## 實作建議分期

1. **原型**：純前端 `CardPicker` + `FlippableCard`，假資料驗證牌堆佈局（桌面/手機）與翻牌動畫手感。
2. **整合**：接 `+page.svelte` tab 與 `+page.server.ts` 抽牌結果，串「點一張翻一張」資料流。
3. **收尾**：未登入暫存流程驗證、celtic-cross 11 張 UX 打磨、響應式調整。

## 已釐清決議

- 牌堆顯示：隨機張數，畫面至少 40 張牌背。
- 手機佈局：網格 + 垂直捲動（扇形無法容納 40+ 張，手機尤甚）。
- 翻牌時序：點一張、翻一張，貼近現實抽牌。
