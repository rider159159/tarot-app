# 功能規格：自定義牌陣（Custom Spread）

> 規劃日期：2026-05-17
> 範圍：在現有抽牌流程新增一種使用者可自選張數的牌陣。需求方為占卜重度使用者。

## 背景

現況抽牌流程提供 5 種固定牌陣（單張、三張時間／問題／直線、凱爾特十字），張數與位置語意都寫死。抽牌頁本來就有「選填問題」欄位（`QuestionInput`）。

痛點：重度使用者有時想擺出較少見、預設選單沒有的陣法，被固定張數限制住。本需求的真正新增點集中在「自選張數」，自定義問題現有功能已覆蓋。

成功衡量：需求方明確表示不以自身使用量衡量，本功能不設量化成長指標，價值評估見下方優先級。

## User Story

作為一個占卜重度使用者，我希望能自選抽牌張數、搭配自己的問題建立牌陣，以便擺出那些較少見、預設選單沒有的陣法。

## Acceptance Criteria

- [ ] `SpreadSelector` 牌陣選擇器新增「自定義」選項
- [ ] 選「自定義」後出現張數選擇器（數字輸入或加減鈕），可選範圍 1～10 張
- [ ] 現有問題欄位（`QuestionInput`）對自定義牌陣同樣可填可不填
- [ ] 送出後後端依使用者指定張數抽牌，沿用現有 Fisher-Yates + 加密 RNG，牌不重複
- [ ] 自定義牌陣不附「靈感牌」：使用者選 N 張就剛好抽 N 張
- [ ] `ReadingDisplay` 能顯示 N 張牌，僅以序號（第 1 張～第 N 張）標示，不賦予位置語意，牌義詮釋由使用者自行決定
- [ ] 占卜紀錄存進 `readings`，`spread_type` 記為 `custom`，張數由 `cards` 陣列長度反推，不另開欄位
- [ ] 歷史紀錄頁照常顯示自定義牌陣的紀錄，不另開獨立頁面
- [ ] 統計頁（`topCards` / `spreadUsage`）照常納入自定義牌陣，`spreadUsage` 多一個「自定義」分類
- [ ] 張數超出 1～10 範圍時後端拒絕並回明確錯誤，前端 UI 也應同步擋下

## 技術影響

### 前端
- `lib/components/SpreadSelector.svelte`：新增「自定義」選項與張數選擇器 UI
- `lib/tarot/spread.ts`：現有 5 種牌陣是固定 config，需讓 custom 表達「動態張數」（非固定位置定義）
- `lib/utils/reading.ts`：`getSpreadName` 要能把 `custom` 對應為「自定義」
- 抽牌請求要把使用者選的張數一起送給後端

### 後端
- `Services/TarotService.cs`：抽牌邏輯目前各牌陣張數寫死，需改成接受動態張數參數；custom 不走 feeling card 分支
- `Models/` 的 `SpreadType` enum 與牌陣設定加入 custom
- 張數需 1～10 上下限驗證（避免 0、負數或超過牌庫 78 張）
- `Services/ReadingService.cs`：建立 reading 時接受 custom 類型

### DB
- migration 005：把 `custom` 加進 `readings.spread_type` 的 CHECK 約束（比照 migration 004 加 `weekly-fortune` 的做法）
- 不需新欄位，張數由 `cards` jsonb 陣列長度反推

### 第三方
- 無

## 優先級評估

- 使用者價值：中。對重度使用者是「能不能擺出想要陣法」的彈性需求，但受眾是進階使用者子集，非全體使用者
- 開發成本：M。前端一個新 UI 元件 + 後端抽牌邏輯參數化 + 一個 migration；無新資料表、無第三方
- 學習收益：把寫死的牌陣設定改成參數化、前端動態表單、用 migration 擴充 CHECK 約束
- 建議順位：可獨立排程，無相依阻塞

## 規劃決策紀錄

規劃階段四項待釐清皆已於 2026-05-17 與需求方確認：

1. 位置語意：v1 不做。只給問題輸入與 N 張牌，牌義由使用者自行詮釋。位置命名留待 v2 視回饋再評估
2. 張數上限：10（對齊凱爾特十字；技術上限為牌庫 78 張）
3. 靈感牌：不附。自定義牌陣的精神是使用者自選張數，系統不再自動多抽
4. 紀錄與統計：自定義牌陣照常進歷史紀錄頁、不開獨立頁；統計頁照常納入
